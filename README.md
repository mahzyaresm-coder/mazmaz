# مقایسه کارمزد برداشت رمزارز

وب‌اپ فارسی با فیلتر ارز و شبکه، دادهٔ اعشاری دقیق، وضعیت برداشت، منبع و زمان دریافت. دادهٔ نامشخص هرگز صفر نمایش داده نمی‌شود.

## اتصال‌های فعلی

| صرافی | منبع تأییدشده | وضعیت آخرین بررسی |
|---|---|---|
| تبدیل | API رسمی استفاده‌شده در صفحهٔ جزئیات کارمزد | ۱۷۸ ردیف برای ۱۶۹ ارز |
| والکس | `https://api.wallex.ir/v1/currencies`، منبع جدول واریز و برداشت | ۲۶۷ ردیف برای ۲۴۸ ارز |
| نوبیتکس | دادهٔ options داخل صفحهٔ pricing | ۳۳۱ ردیف برای ۲۸۰ ارز |
| بیت‌پین | `https://api.bitpin.ir/v1/mkt/network_settings/`، منبع تب برداشت | ۸۰۸ ردیف برای ۶۶۶ ارز؛ همهٔ صفحات خوانده شد |
| افکس | `https://efex.pro/fa/fees`، تب برداشت | HTTP 403؛ parser پیاده نشده |

این تعدادها نتیجهٔ بررسی‌اند و سقف ثابت پوشش نیستند. برنامه در هر چرخه همهٔ ردیف‌های منتشرشده در منبع تأییدشده را می‌خواند. «همهٔ صرافی‌ها» یا تمام ارزهای موجود در حساب کاربران تضمین نشده است.

منبع دقیق بیت‌پین از فایل JavaScript رسمی تب fee پیدا شد. صفحه‌بندی تا انتها خوانده می‌شود؛ شمار کل، چرخه و دامنهٔ next کنترل می‌شوند. کارمزد هر شبکه جداگانه است؛ کارمزد کلی ارز استفاده نمی‌شود. کارمزد درصدی به‌شکل نرخ و با برچسب درصد نمایش داده می‌شود، نه مبلغ ثابت. وضعیت تعمیرات شبکه یا ارز برداشت را متوقف نشان می‌دهد. در آخرین بررسی نوبیتکس دادهٔ قدیمی تحویل داد و با وضعیت stale ثبت شد؛ تعداد ردیف به‌معنی تازگی نیست.

## نسخهٔ بدون سرور و لینک عمومی

`build_pages.py` سایت استاتیک را در `_site` می‌سازد؛ `.github/workflows/pages.yml` روی main دریافت دوره‌ای و انتشار Pages را انجام می‌دهد. نیازی به Render نیست. افکس طبق درخواست کاربر غیرفعال است. فعال‌سازی Public و Pages و موفقیت واقعی Actions پیش‌نیاز لینک عمومی است.

## اجرا و آزمون

```sh
cd /workspace/mazmaz
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
node --check web/app.js
.venv/bin/gunicorn --bind 127.0.0.1:8000 --workers 1 --threads 4 'app:create_app()'
```

این مسیر بلافاصله و سپس هر ۱۵ دقیقه جمع‌آوری می‌کند. مرورگر هر دقیقه snapshot را بازخوانی می‌کند؛ دکمهٔ تازه‌سازی فقط نمایش را بازخوانی می‌کند تا بازدیدکنندگان باعث ارسال انبوه درخواست به صرافی نشوند. `FEE_REFRESH_SECONDS` حداقل ۶۰ ثانیه است.

اجرای توسعه بدون نصب: `python server.py --port 8000`. فقط نمایش snapshot: `python server.py --no-collector`. یک چرخهٔ مستقل: `python collector.py --once`. اگر حتی یک منبع خطا یا دادهٔ قدیمی داشته باشد exit code برابر ۱ می‌شود، اما موفقیت بقیه ذخیره می‌شود. collector مستقل را هم‌زمان با سرور جمع‌آوری‌کننده روی همان فایل اجرا نکنید.

## صحت و تازگی

- snapshot شامل rows، sources و checked_at در `data/fees.json` است؛ کل فایل اتمیک جایگزین می‌شود. `FEE_DATA_FILE` مسیر سرور و `--data` مسیر collector مستقل را تعیین می‌کند.
- شکست منبع زمان آخرین موفقیت و دادهٔ قبلی را حفظ می‌کند. نتیجهٔ خالی یا نامعتبر جایگزین دادهٔ قبلی نمی‌شود. جایگزینی موفق شبکه‌های حذف‌شده را حذف می‌کند.
- در APIهای زنده، updated_at زمان مشاهدهٔ پاسخ است؛ تضمین زمان آخرین تغییر کارمزد در صرافی نیست. در نوبیتکس، زمان query از خود صفحه حفظ می‌شود. دادهٔ بالای یک ساعت قدیمی علامت می‌خورد.
- fallback قدیمی parser صفحهٔ پیش‌ساختهٔ تبدیل برای آزمون و بررسی باقی مانده اما collector اکنون API زنده را می‌خواند؛ شکست API به‌طور مخفی با دادهٔ قدیمی جایگزین نمی‌شود.
- حداقل برداشت مطابق کد رسمی صفحات: تبدیل `min_withdraw - transaction_fee` و والکس `min_withdrawal_value + transaction_fee`. نوبیتکس مستقیم از withdrawMin می‌آید.
- `visible` تبدیل فعال‌بودن برداشت را ثابت نمی‌کند؛ وضعیت آن null است. وضعیت برداشت والکس و نوبیتکس جداگانه خوانده می‌شود. کارمزد شبکهٔ تعلیق‌شده قابل استفاده برای برداشت فعلی نیست.
- شبکه‌های ناشناخته پیشوند صرافی می‌گیرند و خودکار ادغام نمی‌شوند. نمادهای مقیاس‌دار نوبیتکس مثل 1K_SHIB تغییر نام نمی‌کنند تا کارمزد در واحد متفاوت به‌اشتباه مقایسه نشود. آدرس قرارداد در صورت وجود حفظ می‌شود. نماد ارز به‌تنهایی هویت قطعی یک توکن نیست.
- هیچ کلید صرافی یا مجوز معامله و برداشت لازم نیست. HTML و JSON عمومی بدون اجرای JavaScript منبع پردازش می‌شوند.

[راهنمای انتشار و محدودیت‌های میزبانی](DEPLOYMENT.md) — فعال‌سازی و نتیجهٔ deployment را در GitHub بررسی کنید؛ آماده‌بودن فایل‌ها به‌معنی فعال‌شدن سایت نیست.

## ارزهای انتخابی کاربر

فهرست دقیق ۴۳ ارز در assets.py نگهداری می‌شود. فیلتر هم هنگام ذخیرهٔ دریافت، هم هنگام ساخت Pages و هم در API اجرا می‌شود؛ cache یا seed قدیمی باعث بازگشت ارزهای دیگر نمی‌شود. تمام شبکه‌های منبع برای ارزهای انتخابی حفظ می‌شوند. TRON به TRX و XAUt به XAUT یکسان‌سازی می‌شوند. 1K_SHIB نوبیتکس فقط با تأیید مقیاس ۱۰۰۰ و تبدیل دقیق مبالغ به SHIB وارد مقایسه می‌شود. AMZN با AMZNX و توکن‌های هم‌نام خودکار یکی نمی‌شوند. IRR در فهرست است، اما کارمزد بانکی آن هنوز متصل نیست و شبکهٔ رمزارزی برای آن جعل نمی‌شود.

## میانگین فی واقعی بلاک‌چین

با انتخاب یک ارز و یک شبکهٔ مشخص (مثلاً USDT / tron)، جدول همیشه هر چهار صرافی را نشان می‌دهد؛ نبود داده برای یک صرافی «نامشخص» است. کارت جداگانه میانگین فی واقعی پرداخت‌شدهٔ انتقال‌های ساده و موفق را در واحد بومی شبکه، تعداد نمونه، زمان مشاهده، بازهٔ تراکنش‌ها و لینک نمونه‌ها نشان می‌دهد. این داده در `blockchain_fees` همان snapshot ذخیره می‌شود و در Pages و API محلی در دسترس است.

پوشش کدنویسی‌شدهٔ نمونه‌گیرها (موفقیت واقعی هر provider جداگانه بررسی می‌شود):

| شبکه | دارایی/نوع انتقال | واحد فی | منبع |
|---|---|---|---|
| ترون | TRX و USDT با قرارداد مشخص | TRX | TronGrid، solidified |
| بیت‌کوین | BTC پرداخت ساده | BTC | mempool.space |
| اتریوم، BSC، پالیگان، آوالانچ C، سونیک | دارایی بومی و ERC20 با قرارداد یکتای صرافی یا رجیستری بازبینی‌شده | ETH / BNB / POL / AVAX / S | RPC رسمی یا PublicNode |
| آربیتروم | ETH و ERC20 مشخص | ETH | PublicNode؛ gasUsed شامل بخش L1 است و دوباره جمع نمی‌شود |
| سولانا | SOL و USDT/USDC با mint ثابت تأییدشده | SOL | RPC mainnet؛ meta.fee شامل فی امضا/اولویت |
| ریپل | XRP، Payment موفق بومی بدون تبدیل ارزی | XRP | xrplcluster، ledger معتبر |
| استلار | XLM، یک عملیات native payment موفق | XLM | Horizon رسمی، fee_charged |
| لایت‌کوین و دوج‌کوین | پرداخت سادهٔ بومی، گیرنده و change اختیاری | LTC / DOGE | BlockCypher |

هنوز کامل نیست: TON/jetton، کاردانو، بیت‌کوین‌کش، کازموس، فایل‌کوین، Optimism/Base/Linea و توکن‌های بدون قرارداد/mint مشخص نمونه‌گیر کامل ندارند. xStockهای سولانا و TRUMP بدون mint معتبر حدس زده نمی‌شوند. Lightning فی مسیریابی خارج از زنجیره دارد و از transaction fee بلاک‌چین استخراج نمی‌شود. فی یک شبکه به شبکهٔ دیگر کپی نمی‌شود.

`token_registry.json` فقط تطبیق‌های یکتای symbol+chainId از فایل‌های بازبینی‌شدهٔ Uniswap/default-token-list را نگه می‌دارد؛ رجیستری زندهٔ ناشناس بر اساس ticker استفاده نمی‌شود. mintهای USDT/USDC سولانا از solana-labs/token-list روی mainnet و coingeckoId مربوطه تطبیق داده شده‌اند. شناسهٔ قرارداد/mint نمونه‌گیری روی UI نشان داده می‌شود. قرارداد ثبت‌شده در منبع صرافی بر رجیستری مقدم است؛ تضاد چند قرارداد به‌معنی فقدان هویت یکتا است، نه انتخاب تصادفی.

محاسبهٔ آربیتروم بر اساس مستندات رسمی OffchainLabs/arbitrum-docs بررسی شده: `gasUsedForL1` بخشی از `gasUsed` است؛ کل پرداخت `gasUsed * effectiveGasPrice` است. برای انتقال native، gas اجرای خالص باید ۲۱۰۰۰ باشد. نبود فیلد L1 یا ناسازگاری receipt باعث رد نمونه می‌شود. Optimism و Base همین فرمول را ندارند و هنوز غیرفعال‌اند.

`networks.py` تطبیق‌های قطعی بیت‌پین (BNB با عنوان BSC/BEP20، AVAX با عنوان سی‌چین و S با عنوان سونیک) را اصلاح می‌کند. این تطبیق هم روی دریافت جدید و هم cache/seed اعمال می‌شود؛ BNB Beacon یا آوالانچ با نام مبهم خودکار ادغام نمی‌شوند.

هدف ۱۰ نمونهٔ یکتا است. اسکن ترون/EVM به ۸ بلاک اخیر و ۸۰ receipt (حداکثر حدود ۳ دقیقه برای هر provider) محدود است؛ در بیت‌کوین حداکثر دو صفحه از انتهای سه بلاک اخیر خوانده می‌شود. اگر نمونه کمتر باشد، همان تعداد واقعی در مخرج میانگین می‌آید و partial نمایش داده می‌شود. سواپ، batch، تراکنش ناموفق، ERC20 بدون رویداد Transfer مطابق قرارداد/گیرنده/مقدار و native EVM با اجرای قرارداد حذف می‌شوند. فقط legacy/access-list/EIP-1559 پردازش می‌شوند؛ blob و انواع دیگر حذف‌اند. محاسبه با واحدهای صحیح SUN/satoshi/wei و Decimal انجام می‌شود؛ gas limit و maxFeePerGas جایگزین فی واقعی نیستند.

در ترون `TransactionInfo.fee` فی کلِ واقعاً پرداخت‌شده به SUN است. در پاسخ protobuf JSON، scalar حذف‌شده fee به‌معنی صفر است؛ این پیش‌فرض فقط روی receipt موفق و تأییدشده با id/block درست پذیرفته می‌شود. مصرف انرژی یا پهنای باند از منابع حساب می‌تواند فی واقعی را صفر کند، اما هزینهٔ تأمین منابع یا اجارهٔ انرژی در این عدد نیست. میانگین تاریخی تضمین هزینهٔ تراکنش بعدی یا برداشت صرافی نیست و واحدهای متفاوت (مثلاً USDT و TRX) مستقیم مقایسه نمی‌شوند.

APIها فقط خواندنی‌اند؛ کلید خصوصی و اجازهٔ انتقال لازم نیست. در صورت نیاز و پس از تشخیص محدودیت provider می‌توان TRONGRID_API_KEY را به‌صورت امن در محیط اجرا تنظیم کرد؛ مقدار آن نباید در کد یا snapshot قرار بگیرد. هیچ کلید جدیدی برای اجرای فعلی تهیه یا درخواست نشده است.

خطای provider یا صفر نمونهٔ معتبر، میانگین قبلی و زمانش را حفظ می‌کند؛ آن را تازه نمی‌کند. اطلاعات بالای یک ساعت یا نمونه‌های قدیمی علامت‌گذاری می‌شوند. cache و seed زمان‌بندی Pages همان قوانین قبلی را دارند. در اولین بررسی این قابلیت، شبکهٔ محیط توسعه درخواست به APIهای بلاک‌چین را با proxy 403 مسدود کرد؛ آزمون‌های محاسباتی و UI اجرا شده‌اند اما موفقیت عدد زنده از این محیط هنوز تأیید نشده است. GitHub Actions از شبکهٔ خودش درخواست می‌فرستد و وضعیت واقعی هر provider را در خروجی ثبت می‌کند.

### بررسی اختلاف فی یک تراکنش و میانگین

نمایش میانگین اکنون جمع فی، کمترین، بیشترین و میانه را هم دارد و فهرست نمونه‌ها به‌صورت باز نمایش داده می‌شود. در ترون، هر نمونه علاوه بر fee کل، سهم energy_fee و net_fee (با واحد TRX) و energy_usage_total (تعداد واحد انرژی، نه TRX) را نگه می‌دارد. مجموع اجزای پرداختی نباید از fee کل بیشتر باشد؛ پاسخ ناسازگار رد می‌شود. فرمول میانگین و معیار انتخاب نمونه تغییر نکرده و نمونهٔ گران صرفاً به‌خاطر گران بودن حذف نمی‌شود. میانه فقط شاخص کمکی است، نه جایگزین میانگین درخواستی کاربر. آزمون با مقادیر فرضی برای نشان‌دادن حساسیت میانگین به دادهٔ پرت، بازسازی تراکنش‌های واقعی سایت محسوب نمی‌شود. اختلاف عدد گزارش‌شدهٔ کاربر تا دسترسی به همان ده hash و receipt همچنان نیازمند بررسی است.

محدودیت اسکن شبکه‌های جدید: سولانا پنج slot finalized، ریپل چهار ledger validated، استلار ۵۰ تراکنش و حداکثر ۳۵ درخواست جزئیات عملیات، LTC/DOGE دو بلاک و حداکثر ۳۰ transaction receipt با سقف زمانی سه دقیقه. هزینهٔ rent سولانا، مالیات توکن و اجارهٔ منابع ترون با network fee یکی نیستند و در این میانگین افزوده نمی‌شوند.
