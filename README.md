# مقایسه کارمزد برداشت رمزارز

وب‌اپ فارسی با فیلتر ارز و شبکه، دادهٔ اعشاری دقیق، وضعیت برداشت، منبع و زمان دریافت. دادهٔ نامشخص هرگز صفر نمایش داده نمی‌شود.

## اتصال‌های فعلی

| صرافی | منبع تأییدشده | وضعیت آخرین بررسی |
|---|---|---|
| تبدیل | API رسمی استفاده‌شده در صفحهٔ جزئیات کارمزد | ۱۷۸ ردیف برای ۱۶۹ ارز |
| والکس | `https://api.wallex.ir/v1/currencies`، منبع جدول واریز و برداشت | ۲۶۷ ردیف برای ۲۴۸ ارز |
| نوبیتکس | دادهٔ options داخل صفحهٔ pricing | ۳۳۱ ردیف برای ۲۸۰ ارز |
| بیت‌پین | `https://api.bitpin.ir/v1/mkt/network_settings/`، منبع تب برداشت | ۸۰۸ ردیف برای ۶۶۶ ارز؛ همهٔ صفحات خوانده شد |
| افکس | `https://efex.pro/fa/fees`، تب برداشت | HTTP 403؛ parser پیاده نشده |

این تعدادها نتیجهٔ بررسی‌اند و سقف ثابت پوشش نیستند. برنامه در هر چرخه همهٔ ردیف‌های منتشرشده در منبع تأییدشده را می‌خواند. «همهٔ صرافی‌ها» یا تمام ارزهای موجود در حساب کاربران تضمین نشده است.

منبع دقیق بیت‌پین از فایل JavaScript رسمی تب fee پیدا شد. صفحه‌بندی تا انتها خوانده می‌شود؛ شمار کل، چرخه و دامنهٔ next کنترل می‌شوند. کارمزد هر شبکه جداگانه است؛ کارمزد کلی ارز استفاده نمی‌شود. کارمزد درصدی به‌شکل نرخ و با برچسب درصد نمایش داده می‌شود، نه مبلغ ثابت. وضعیت تعمیرات شبکه یا ارز برداشت را متوقف نشان می‌دهد. در آخرین بررسی نوبیتکس دادهٔ قدیمی تحویل داد و با وضعیت stale ثبت شد؛ تعداد ردیف به‌معنی تازگی نیست.

## نسخهٔ بدون سرور و لینک عمومی

`build_pages.py` سایت استاتیک را در `_site` می‌سازد؛ `.github/workflows/pages.yml` روی main دریافت دوره‌ای و انتشار Pages را انجام می‌دهد. نیازی به Render نیست. افکس طبق درخواست کاربر غیرفعال است. فعال‌سازی Public و Pages و موفقیت واقعی Actions پیش‌نیاز لینک عمومی است.

## اجرا و آزمون

```sh
cd /workspace/mazmaz
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
node --check web/app.js
.venv/bin/gunicorn --bind 127.0.0.1:8000 --workers 1 --threads 4 'app:create_app()'
```

این مسیر بلافاصله و سپس هر ۱۵ دقیقه جمع‌آوری می‌کند. مرورگر هر دقیقه snapshot را بازخوانی می‌کند؛ دکمهٔ تازه‌سازی فقط نمایش را بازخوانی می‌کند تا بازدیدکنندگان باعث ارسال انبوه درخواست به صرافی نشوند. `FEE_REFRESH_SECONDS` حداقل ۶۰ ثانیه است.

اجرای توسعه بدون نصب: `python server.py --port 8000`. فقط نمایش snapshot: `python server.py --no-collector`. یک چرخهٔ مستقل: `python collector.py --once`. اگر حتی یک منبع خطا یا دادهٔ قدیمی داشته باشد exit code برابر ۱ می‌شود، اما موفقیت بقیه ذخیره می‌شود. collector مستقل را هم‌زمان با سرور جمع‌آوری‌کننده روی همان فایل اجرا نکنید.

## صحت و تازگی

- snapshot شامل rows، sources و checked_at در `data/fees.json` است؛ کل فایل اتمیک جایگزین می‌شود. `FEE_DATA_FILE` مسیر سرور و `--data` مسیر collector مستقل را تعیین می‌کند.
- شکست منبع زمان آخرین موفقیت و دادهٔ قبلی را حفظ می‌کند. نتیجهٔ خالی یا نامعتبر جایگزین دادهٔ قبلی نمی‌شود. جایگزینی موفق شبکه‌های حذف‌شده را حذف می‌کند.
- در APIهای زنده، updated_at زمان مشاهدهٔ پاسخ است؛ تضمین زمان آخرین تغییر کارمزد در صرافی نیست. در نوبیتکس، زمان query از خود صفحه حفظ می‌شود. دادهٔ بالای یک ساعت قدیمی علامت می‌خورد.
- fallback قدیمی parser صفحهٔ پیش‌ساختهٔ تبدیل برای آزمون و بررسی باقی مانده اما collector اکنون API زنده را می‌خواند؛ شکست API به‌طور مخفی با دادهٔ قدیمی جایگزین نمی‌شود.
- حداقل برداشت مطابق کد رسمی صفحات: تبدیل `min_withdraw - transaction_fee` و والکس `min_withdrawal_value + transaction_fee`. نوبیتکس مستقیم از withdrawMin می‌آید.
- `visible` تبدیل فعال‌بودن برداشت را ثابت نمی‌کند؛ وضعیت آن null است. وضعیت برداشت والکس و نوبیتکس جداگانه خوانده می‌شود. کارمزد شبکهٔ تعلیق‌شده قابل استفاده برای برداشت فعلی نیست.
- شبکه‌های ناشناخته پیشوند صرافی می‌گیرند و خودکار ادغام نمی‌شوند. نمادهای مقیاس‌دار نوبیتکس مثل 1K_SHIB تغییر نام نمی‌کنند تا کارمزد در واحد متفاوت به‌اشتباه مقایسه نشود. آدرس قرارداد در صورت وجود حفظ می‌شود. نماد ارز به‌تنهایی هویت قطعی یک توکن نیست.
- هیچ کلید صرافی یا مجوز معامله و برداشت لازم نیست. HTML و JSON عمومی بدون اجرای JavaScript منبع پردازش می‌شوند.
